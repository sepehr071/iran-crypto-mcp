# راهنمای عیب‌یابی MCP در Claude Code

اگر سرور MCP در Claude Code دیده نمی‌شود، وضعیتش **Failed** است یا اصلاً اجرا نمی‌شود، اینجا به شکل «اگر این شد ← این کار را بکنید» قدم‌به‌قدم توضیح داده شده است. دستورها برای ویندوز، مک و لینوکس جدا نوشته شده‌اند. اگر هنوز Claude Code را نصب نکرده‌اید، از بخش [شروع سریع](#start) شروع کنید.

- **محیط:** Claude Code در ترمینال و افزونهٔ VS Code
- **سیستم‌عامل:** ویندوز · macOS · لینوکس
- **نسخه:** دستورها با Claude Code نسخهٔ 2.1.220 بررسی شده‌اند. اگر نسخهٔ شما فرق دارد، `claude mcp --help` و `claude mcp add --help` مرجع دقیق گزینه‌هاست.
- **بازبینی:** ۲۰ آبان ۱۴۰۵
- **نکته:** نام سرور `iran-crypto` در این راهنما فقط یک نمونه است؛ جایش نام سرور خودتان را بگذارید.

## <a id="start"></a>شروع سریع: نصب و استفاده از Claude Code

Claude Code را می‌شود در **ترمینال** یا به‌صورت **افزونه در VS Code** استفاده کرد. هر دو را می‌توانید نصب کنید؛ سرورهای MCP و تنظیمات بین هر دو مشترک است. اگر فقط یکی را می‌خواهید، همان قسمت را بخوانید.

**اگر Claude Code همین الان روی سیستم شما نصب است، از بخش نصب رد شوید و مستقیم به مرحلهٔ بعد بروید: [نصب iran-crypto-mcp](#first-mcp).**

برای اینکه بفهمید نصب است: در ترمینال `claude --version` را بزنید؛ اگر شمارهٔ نسخه آمد، نصب است. در VS Code هم اگر افزونهٔ «Claude Code» را در Extensions می‌بینید، افزونه نصب است.

**پیش‌نیازها:**

- سیستم‌عامل: macOS 13 یا بالاتر، Windows 10 (نسخهٔ 1809 به بالا)، Ubuntu 20.04+ یا Debian 10+ (Alpine هم از 3.19 به بالا). حداقل ۴ گیگابایت RAM و اینترنت.
- یک حساب Claude: اشتراک Pro، Max، Team یا Enterprise، یا حساب Claude Console. کلید API لازم نیست.
- برای افزونه: VS Code نسخهٔ 1.94 یا بالاتر.
- در ویندوز: نصب [Git for Windows](https://git-scm.com/downloads/win) توصیه می‌شود؛ بدون آن Claude از PowerShell استفاده می‌کند. در WSL لازم نیست.
- طبق مستندات رسمی، استفاده فقط در [کشورهای پشتیبانی‌شده](https://www.anthropic.com/supported-countries) ممکن است. اگر موقع نصب یا ورود خطای دسترسی (مثل ۴۰۳) دیدید، علتش ممکن است همین باشد.

### <a id="cli"></a>راه ۱: ترمینال

#### گام ۱: نصب

دستور سیستم‌عامل خودتان را در ترمینال بزنید. این دستور موقع دانلود چیزی نمایش نمی‌دهد؛ صبر کنید تمام شود.

**ویندوز (PowerShell):**

<div dir="ltr">

```powershell
irm https://claude.ai/install.ps1 | iex
```

</div>

یا با winget:

<div dir="ltr">

```powershell
winget install Anthropic.ClaudeCode
```

</div>

<details>
<summary>ترمینال من CMD است، نه PowerShell</summary>

اگر خط فرمان با &lrm;`PS C:\`&lrm; شروع می‌شود، PowerShell است؛ اگر فقط &lrm;`C:\`&lrm; است، CMD است. در CMD این دستور را بزنید:

<div dir="ltr">

```bat
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

</div>

اگر پیام `The token '&&' is not a valid statement separator` دیدید، در PowerShell هستید؛ اگر &lrm;`'irm' is not recognized`&lrm; دیدید، در CMD هستید و باید دستور CMD را بزنید.

</details>

**مک:**

<div dir="ltr">

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

</div>

یا با Homebrew:

<div dir="ltr">

```bash
brew install --cask claude-code
```

</div>

**لینوکس و WSL:**

<div dir="ltr">

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

</div>

اگر Node.js نسخهٔ 22 یا بالاتر دارید، روی هر سیستم‌عامل می‌توانید با npm هم نصب کنید (بدون `sudo`):

<div dir="ltr">

```bash
npm install -g @anthropic-ai/claude-code
```

</div>

دستورهای «curl … | bash» و «irm … | iex» کدی را از اینترنت دانلود و اجرا می‌کنند. اگر نگرانید، [بخش امنیت](#security) را ببینید یا از winget / Homebrew استفاده کنید.

**بررسی نصب:** وقتی نصب تمام شد، یک ترمینال **جدید** باز کنید و بزنید:

<div dir="ltr">

```bash
claude --version
```

</div>

اگر شمارهٔ نسخه چاپ شد، نصب درست است. اگر گفت `claude` پیدا نمی‌شود ← [مورد ۳](#case-3). برای بررسی کامل سلامت نصب هم می‌توانید `claude doctor` را بزنید.

نصب با اسکریپت خودش آپدیت می‌شود، ولی Homebrew و winget خودکار آپدیت نمی‌شوند؛ هر چند وقت یک بار `brew upgrade claude-code` یا `winget upgrade Anthropic.ClaudeCode` را بزنید.

#### گام ۲: اولین اجرا و ورود به حساب

ترمینال را در پوشهٔ پروژه‌تان باز کنید و بزنید:

<div dir="ltr">

```bash
cd your-project-folder
claude
```

</div>

بار اول از شما می‌خواهد وارد حساب شوید (لاگین): مرورگر باز می‌شود، ورود را تأیید کنید و برگردید. این ورود ذخیره می‌شود و دفعهٔ بعد لازم نیست دوباره وارد شوید. بعد از آن، هر چیزی را به زبان ساده بپرسید؛ مثلاً «این پروژه چه کاری می‌کند؟».

#### گام ۳: دستورهای پرکاربرد

| دستور | کارش |
| --- | --- |
| &lrm;`/help`&lrm; | لیست دستورها (داخل Claude) |
| &lrm;`/login`&lrm; | ورود دوباره یا عوض کردن حساب |
| &lrm;`/resume`&lrm; | ادامهٔ یک گفتگوی قبلی |
| &lrm;`/mcp`&lrm; | وضعیت و مدیریت سرورهای MCP |
| &lrm;`/exit`&lrm; یا دو بار `Ctrl+D` | خروج از Claude |
| &lrm;`claude -p "your question"`&lrm; | فقط یک سؤال می‌پرسد، جواب را چاپ می‌کند و تمام می‌شود (مناسب اسکریپت) |
| `claude -c` | ادامهٔ آخرین گفتگو |
| `claude -r` | انتخاب و ادامهٔ یکی از گفتگوهای قبلی |

### <a id="vscode"></a>راه ۲: افزونهٔ VS Code

#### گام ۱: نصب افزونه

VS Code باید نسخهٔ 1.94 یا بالاتر باشد. `Ctrl+Shift+X` (در مک &lrm;`⌘+Shift+X`&lrm;) را بزنید، «Claude Code» را جستجو کنید (ناشر: Anthropic) و **Install** را بزنید. یا از ترمینال:

<div dir="ltr">

```bash
code --install-extension anthropic.claude-code
```

</div>

اگر بعد از نصب افزونه دیده نشد، VS Code را ببندید و دوباره باز کنید، یا از Command Palette گزینهٔ `Developer: Reload Window` را بزنید.

#### گام ۲: باز کردن پنل Claude

آیکن جرقه (Spark) نشانهٔ Claude Code است. یکی از این راه‌ها:

- آیکن Spark در نوار ابزار بالا و سمت راستِ ویرایشگر (فقط وقتی یک فایل باز است)
- آیکن Spark در نوار کناریِ سمت چپ (Activity Bar؛ همیشه هست)
- Command Palette (`Ctrl+Shift+P`، در مک &lrm;`⌘+Shift+P`&lrm;)، عبارت «Claude Code» را تایپ کنید و مثلاً `Open in New Tab` را بزنید
- عبارت **✻ Claude Code** در نوار وضعیتِ پایین و سمت راست

#### گام ۳: ورود به حساب

بار اول یک صفحهٔ ورود می‌آید؛ **Sign in** را بزنید و در مرورگر تأیید کنید. اگر بعداً پیام `Not logged in · Please run /login` دیدید، در چت &lrm;`/login`&lrm; را بزنید یا پنجره را با `Developer: Reload Window` ریلود کنید.

#### گام ۴: شروع کار

در پنل هر چیزی را بپرسید. متنی که در ویرایشگر انتخاب کرده‌اید را Claude خودکار می‌بیند؛ `Alt+K` (در مک `Option+K`) یک ارجاع به همان خط‌ها (مثل &lrm;`@file.ts#5-10`&lrm;) داخل پیام می‌گذارد.

**نکتهٔ مهم:** افزونه یک نسخهٔ خصوصی از Claude Code را برای پنل چت همراه خودش دارد، ولی دستور `claude` را روی ترمینال شما نصب **نمی‌کند**. اگر می‌خواهید در ترمینال (حتی ترمینال داخل VS Code، از منوی Terminal ← New Terminal) `claude` یا `claude mcp add` بزنید، باید «راه ۱» را هم انجام دهید.

### <a id="first-mcp"></a>اولین سرور MCP: نصب و استفاده از iran-crypto-mcp

سرور MCP به Claude اجازه می‌دهد از یک ابزار یا دادهٔ بیرونی استفاده کند. اینجا سرور نمونهٔ `iran-crypto` (قیمت صرافی‌های ایرانی) را اضافه می‌کنیم؛ جای آن می‌توانید سرور خودتان را بگذارید.

#### گام ۱: پیش‌نیاز اجرای سرور

این سرور پایتونی است و با `uvx` اجرا می‌شود، پس باید ابزار **uv** نصب باشد (سرورهای Node به Node.js نیاز دارند). نصبشان در [مورد ۳](#case-3) آمده است.

#### گام ۲: اضافه کردن سرور

در ترمینال (داخل پوشهٔ پروژه یا هرجا) بزنید:

<div dir="ltr">

```bash
claude mcp add iran-crypto -s user -- uvx iran-crypto-mcp
```

</div>

&lrm;`-s user`&lrm; یعنی برای همهٔ پروژه‌های شما (توضیح بیشتر در [بخش scope](#scopes)). در VS Code هم می‌توانید در پنل چت &lrm;`/mcp`&lrm; را بزنید و **Add server** را انتخاب کنید؛ نتیجه یکی است.

#### گام ۳: یک گفتگوی جدید باز کنید

سرورها فقط موقع شروع گفتگو بارگذاری می‌شوند؛ سروری که همین الان اضافه کرده‌اید در گفتگوی فعلی دیده نمی‌شود.

#### گام ۴: وضعیت را ببینید

در گفتگوی جدید &lrm;`/mcp`&lrm; را بزنید. کنار نام سرور باید &lrm;`✓ Connected`&lrm; باشد. اگر نبود، از بخش «اگر این شد ← به این مورد بروید» پایین‌تر ادامه دهید.

#### گام ۵: استفاده

مثل همیشه، به زبان ساده بخواهید؛ Claude خودش ابزار مناسب را پیدا می‌کند و بار اول برای استفاده از آن اجازه می‌پرسد. مثلاً: «با سرور iran-crypto قیمت تتر را در صرافی‌های ایرانی مقایسه کن».

## اول بفهمیم مشکل از کجاست

یک سرور MCP برنامهٔ کوچکی است که Claude را به یک ابزار یا منبع داده وصل می‌کند (مثلاً قیمت صرافی‌ها، Figma یا پایگاه‌داده). برای اینکه کار کند سه چیز باید درست باشد، و تقریباً هر مشکلی در یکی از همین سه جاست:

1. **اضافه کردن سرور:** سرور باید در جای درستی (scope) اضافه شده باشد تا Claude در این پروژه آن را ببیند.
2. **برنامهٔ اجرا:** برنامه‌ای که سرور را اجرا می‌کند، مثل `uvx` یا `npx` یا `node`، باید نصب باشد و Claude بتواند آن را پیدا کند.
3. **گفتگوی فعلی:** سرورها فقط موقع شروع گفتگو بارگذاری می‌شوند؛ سروری که بعد از شروع گفتگو اضافه کنید، تا گفتگوی بعدی دیده نمی‌شود.

## <a id="case-1"></a>مورد ۱: سرور اصلاً در لیست &lrm;`/mcp`&lrm; نیست

یعنی Claude در این گفتگو هیچ سروری با این اسم پیدا نکرده و هنوز سراغ اجرای سرور هم نرفته. پس مشکل از «اضافه شدن سرور» یا «گفتگوی فعلی» است، نه خودِ برنامه.

#### اگر `claude mcp list` (در پوشهٔ همان پروژه) سرور را نشان نمی‌دهد

**آنگاه** سرور جای دیگری اضافه شده است؛ معمولاً با scope پیش‌فرض (`local`) برای مسیر یک پوشهٔ دیگر. آن را در **user scope** اضافه کنید که به مسیر پوشه وابسته نیست و در همهٔ پروژه‌ها دیده می‌شود:

<div dir="ltr">

```bash
claude mcp remove iran-crypto
claude mcp add iran-crypto -s user -- uvx iran-crypto-mcp
```

</div>

اگر `remove` گفت چنین سروری نیست، اشکالی ندارد. علامت &lrm;`--`&lrm; قبل از `uvx` را حتماً بگذارید؛ بدون آن گزینه‌های سرور با گزینه‌های خود Claude قاطی می‌شود.

#### اگر در `claude mcp list` هست ولی در &lrm;`/mcp`&lrm; نیست

**آنگاه** گفتگوی شما قبل از اضافه شدن سرور شروع شده است. یک **گفتگوی جدید** باز کنید (در ترمینال: `claude` را ببندید و دوباره اجرا کنید). اگر نشد، [مورد ۵](#case-5).

#### اگر سرور را از طریق فایل &lrm;`.mcp.json`&lrm; در پروژه گذاشته‌اید

**آنگاه** [مورد ۶](#case-6) (تأیید) و [مورد ۸](#case-8) (خطای JSON) را ببینید.

#### اگر حتی خودِ دستور `claude` هم پیدا نمی‌شود

**آنگاه** [مورد ۳](#case-3).

**نمونهٔ واقعی:** سرور `iran-crypto` (با `uvx`) در scope محلی و برای مسیر &lrm;`E:/Projects/…`&lrm; ذخیره شده بود، در حالی که VS Code همان پوشه را با مسیر &lrm;`e:\Projects\…`&lrm; باز کرده بود؛ در &lrm;`/mcp`&lrm; هیچ اثری از آن نبود. دوباره اضافه کردن سرور با &lrm;`-s user`&lrm; و باز کردن یک گفتگوی جدید مشکل را حل کرد. (علت دقیق معلوم نیست؛ بیشتر احتمال دارد فرق مسیر بوده یا گفتگو قبل از اضافه شدن سرور شروع شده بوده. به همین دلیل user scope راه مطمئن‌تری است.)

## <a id="case-2"></a>مورد ۲: وضعیت ✗ Failed

سرور درست اضافه شده و Claude سعی کرده آن را اجرا کند، ولی اجرا یا اتصال موفق نبوده. اولین کار همان [تست ۳](#test-3) است: دستور را دستی بزنید تا پیام واقعی را ببینید.

#### اگر دستی هم پیام `not recognized`، `command not found` یا `ENOENT` می‌دهد

**آنگاه** برنامهٔ اجرا (مثل `uvx`) نصب نیست یا در PATH نیست ← [مورد ۳](#case-3).

#### اگر دستی هم خطا می‌دهد (نام پکیج، نسخهٔ پایتون/نود، `ModuleNotFoundError`…)

**آنگاه** خطا مال خود سرور است، نه Claude. اسم پکیج را حرف‌به‌حرف با مستندات مقایسه کنید و کش را رفرش کنید:

<div dir="ltr">

```bash
uvx --refresh iran-crypto-mcp
```

</div>

#### اگر دستی درست اجرا می‌شود ولی داخل Claude Failed می‌شود

**آنگاه** معمولاً اجرای اول به دانلود نیاز دارد و بیشتر از تایم‌اوت شروع طول می‌کشد. دو راه:

- یک بار دستی اجرا کنید تا پکیج دانلود و کش شود، بعد در &lrm;`/mcp`&lrm; دوباره وصل شوید.
- تایم‌اوت شروع را بیشتر کنید (برای `claude` در ترمینال؛ در VS Code راه اول ساده‌تر است). دستورش:

**ویندوز (PowerShell):**

<div dir="ltr">

```powershell
$env:MCP_TIMEOUT = 60000; claude
```

</div>

**مک و لینوکس:**

<div dir="ltr">

```bash
MCP_TIMEOUT=60000 claude
```

</div>

#### اگر موقع دانلود خطای شبکه می‌گیرید (۴۰۳، timeout، SSL، `ECONNRESET`) از PyPI، npm یا GitHub

**آنگاه** مشکل دسترسی شبکه است، نه تنظیم Claude. با `curl -I https://pypi.org` (یا `https://registry.npmjs.org` برای npm) چک کنید به آن سایت دسترسی دارید. اگر محدودیت منطقه‌ای یا شبکه‌ای است، از شبکه/پروکسی‌ای که دسترسی دارد یا یک mirror مورد اعتماد سازمانتان استفاده کنید:

<details>
<summary>تنظیم پروکسی یا mirror برای uv و npm</summary>

**ویندوز (PowerShell):**

<div dir="ltr">

```powershell
$env:HTTPS_PROXY = "http://HOST:PORT"
$env:UV_DEFAULT_INDEX = "<mirror-url>"
npm config set registry <mirror-url>
```

</div>

**مک و لینوکس:**

<div dir="ltr">

```bash
export HTTPS_PROXY="http://HOST:PORT"
export UV_DEFAULT_INDEX="<mirror-url>"
npm config set registry <mirror-url>
```

</div>

&lrm;`<mirror-url>`&lrm; و `HOST:PORT` را با مقدارهای واقعیِ شبکهٔ خودتان عوض کنید. این متغیرها باید در محیطی باشند که `claude` یا VS Code از آن شروع می‌شود ([مورد ۵](#case-5)).

</details>

#### اگر روی خودِ ویندوز کار می‌کنید (نه WSL) و سرور با `npx` اجرا می‌شود و پیام `Connection closed` می‌بینید

**آنگاه** `npx` در ویندوز یک فایل &lrm;`.cmd`&lrm; است و ممکن است بدون `cmd /c` اجرا نشود. این را امتحان کنید:

<div dir="ltr">

```powershell
claude mcp add my-server -s user -- cmd /c npx -y <package-name>
```

</div>

این راه‌حل در مستندات رسمیِ فعلی نیامده و در نسخه‌های جدید ممکن است لازم نباشد؛ اگر بدون آن کار می‌کند، نیازی به آن نیست. برای `uvx` هم لازم نیست؛ آن یک فایل اجرایی واقعی (&lrm;`.exe`&lrm;) است.

#### اگر سرور کلید API یا توکن می‌خواهد و خطای «missing key / unauthorized» می‌دهد

**آنگاه** متغیر را موقع اضافه کردن سرور به آن بدهید:

<div dir="ltr">

```bash
claude mcp add my-server -s user -e API_KEY=your-key -- uvx my-mcp-server
```

</div>

کلید را داخل فایل &lrm;`.mcp.json`&lrm; که در git می‌رود ننویسید ([بخش امنیت](#security)).

#### اگر سرور از راه دور است (یک آدرس &lrm;`https://…`&lrm; دارد، نه دستوری که روی سیستم خودتان اجرا شود)

**آنگاه** آدرس را با &lrm;`claude mcp get <name>`&lrm; مقایسه کنید؛ VPN یا فایروال سازمان را بررسی کنید؛ اگر نیاز به ورود دارد ← [مورد ۴](#case-4). نمونهٔ درست:

<div dir="ltr">

```bash
claude mcp add --transport http my-server https://example.com/mcp
```

</div>

## <a id="case-3"></a>مورد ۳: «not recognized» / «command not found»

Claude فقط برنامه‌هایی را اجرا می‌کند که در PATH **همان برنامه‌ای که Claude را راه انداخته** باشند. ممکن است در یک ترمینال جدید کار کند ولی در VS Code نه، چون VS Code PATH قدیمی خودش را نگه داشته است.

### مرحلهٔ اول: ببینید پیدا می‌شود یا نه

**ویندوز (PowerShell):**

<div dir="ltr">

```powershell
Get-Command uvx
Get-Command npx
Get-Command claude
```

</div>

**مک و لینوکس:**

<div dir="ltr">

```bash
command -v uvx
command -v npx
command -v claude
```

</div>

#### اگر هیچ مسیری چاپ نشد (برنامه نصب نیست)

**آنگاه** نصبش کنید. `uvx` بخشی از ابزار **uv** است (برای سرورهای پایتونی)؛ `npx` همراه **Node.js** می‌آید:

**ویندوز:**

<div dir="ltr">

```powershell
winget install --id=astral-sh.uv -e
winget install OpenJS.NodeJS.LTS
```

</div>

بدون winget: `pip install uv` یا فایل نصب رسمی از سایت astral.sh/uv.

**مک:**

<div dir="ltr">

```bash
brew install uv node
```

</div>

بدون Homebrew: `curl -LsSf https://astral.sh/uv/install.sh | sh` (قبلش به [هشدار امنیتی](#security) نگاه کنید).

**لینوکس:**

<div dir="ltr">

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

</div>

اگر curl ندارید: `wget -qO- https://astral.sh/uv/install.sh | sh`. یا `pipx install uv`. Node.js را با package manager توزیعتان (مثل apt یا dnf) یا با nvm نصب کنید.

#### اگر بعد از نصب در ترمینال جدید پیدا می‌شود ولی در VS Code / Claude نه

**آنگاه** VS Code با PATH قدیمی بالا آمده. «Reload Window» کافی نیست؛ **کل برنامه** را ببندید و دوباره باز کنید:

- **ویندوز:** همهٔ پنجره‌های VS Code را ببندید و در Task Manager مطمئن شوید پروسه‌ای به اسم `Code` باقی نمانده؛ بعد دوباره باز کنید.
- **مک:** با &lrm;`⌘+Q`&lrm; کامل ببندید (بستن فقط پنجره کافی نیست). بهتر است از ترمینال با &lrm;`code .`&lrm; باز کنید تا PATH ترمینال را از آن بگیرد.
- **لینوکس:** همهٔ پنجره‌های VS Code را ببندید. اگر uv در &lrm;`~/.local/bin`&lrm; نصب شده و هنوز دیده نمی‌شود، یک بار لاگ‌اوت و دوباره لاگین کنید (در بسیاری از توزیع‌ها مثل اوبونتو، &lrm;`~/.profile`&lrm; این پوشه را فقط موقع لاگین به PATH اضافه می‌کند).

#### اگر باز هم پیدا نشد، یا VS Code را از Dock / منوی برنامه‌ها باز می‌کنید و PATH ترمینال را نمی‌بیند

**آنگاه** **راه مطمئن:** مسیر کامل برنامه را به‌جای اسمش بنویسید تا به PATH وابسته نباشد.

**ویندوز (PowerShell):**

<div dir="ltr">

```powershell
(Get-Command uvx).Source
claude mcp remove iran-crypto
claude mcp add iran-crypto -s user -- "C:\Users\<name>\AppData\Local\Microsoft\WinGet\Links\uvx.exe" iran-crypto-mcp
```

</div>

مسیر داخل کوتیشن را با خروجی دستور اول عوض کنید (اگر uv را با فایل نصب رسمی نصب کرده‌اید معمولاً `C:\Users\<name>\.local\bin\uvx.exe` است).

**مک و لینوکس:**

<div dir="ltr">

```bash
claude mcp remove iran-crypto
claude mcp add iran-crypto -s user -- "$(command -v uvx)" iran-crypto-mcp
```

</div>

#### اگر مک یا لینوکس هستید و می‌خواهید خود uv همیشه در ترمینال‌ها پیدا شود

**آنگاه** پوشهٔ نصب را به PATH ترمینال اضافه کنید و ترمینال را ببندید و باز کنید:

**مک (zsh):**

<div dir="ltr">

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
```

</div>

**لینوکس (bash):**

<div dir="ltr">

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.profile
```

</div>

**ویندوز:** فایل نصب رسمی و winget خودشان PATH را تنظیم می‌کنند؛ فقط کافی است ترمینال و VS Code را کامل ببندید و باز کنید.

## <a id="case-4"></a>مورد ۴: وضعیت ⚠ Needs Auth

سرور اجرا می‌شود ولی برای استفاده باید لاگین کنید (OAuth)؛ مثل Gmail، Slack یا Canva در لیست &lrm;`/mcp`&lrm;.

#### اگر سرور از نوع «claude.ai» است (Gmail، Slack، Google Drive، Canva…)

**آنگاه** از تنظیمات Connectors در خود claude.ai وصلش کنید، نه از ترمینال.

#### اگر سرور را خودتان با &lrm;`--transport http`&lrm; اضافه کرده‌اید

**آنگاه** در گفتگو &lrm;`/mcp`&lrm; را بزنید، سرور را انتخاب کنید و گزینهٔ Authenticate (لاگین) را بزنید؛ مرورگر باز می‌شود و بعد از لاگین دوباره به Claude برمی‌گردد.

#### اگر مرورگر باز نشد یا برگشت به `localhost` کار نکرد

**آنگاه** ممکن است پورت اشغال باشد یا سرور آدرس برگشتِ ثابت بخواهد. موقع اضافه کردن سرور می‌توانید پورت ثابت بدهید: &lrm;`--callback-port <port>`&lrm; (و در صورت نیاز &lrm;`--client-id`&lrm;).

#### اگر Claude را داخل اسکریپت، CI یا SDK اجرا می‌کنید (یعنی کسی پای ترمینال نیست)

**آنگاه** لاگین (OAuth) آنجا امکان ندارد؛ یک بار در ترمینال یا VS Code معمولی لاگین کنید.

## <a id="case-5"></a>مورد ۵: تغییر دادم ولی هنوز همان مشکل را دارم

بیشتر وقت‌ها که بعد از تغییر هنوز مشکل هست، یعنی تغییر انجام شده ولی برنامه‌ای که باید آن را ببیند هنوز با وضعیت قبلی باز مانده. جدول زیر می‌گوید بعد از هر تغییر چه کاری لازم است:

| اگر این را تغییر دادید | آنگاه این لازم است |
| --- | --- |
| اضافه یا حذف کردن سرور (`claude mcp add/remove`) | یک **گفتگوی جدید** باز کنید (در ترمینال: خروج از `claude` و اجرای دوباره). اگر در &lrm;`/mcp`&lrm; گزینهٔ Reconnect دارد، می‌توانید آن را هم امتحان کنید. |
| ویرایش فایل &lrm;`.mcp.json`&lrm; | گفتگوی جدید؛ و اگر سرور جدید است، تأیید دوباره ([مورد ۶](#case-6)). |
| نصب برنامه یا تغییر PATH (uv، node…) | بستن **کامل** VS Code و ترمینال و باز کردن دوباره. «Reload Window» کافی نیست چون متغیرهای محیطی را عوض نمی‌کند. |
| متغیر محیطی (`MCP_TIMEOUT`، پروکسی، mirror) | برنامه باید از محیطی شروع شود که آن متغیر را دارد؛ یعنی VS Code را از همان ترمینال با &lrm;`code .`&lrm; اجرا کنید یا متغیر را دائمی کنید. |
| به‌روزرسانی Claude Code یا افزونه | ریستارت افزونه / پنجرهٔ VS Code. |
| پوشه‌ای که ترمینال در آن `claude mcp add` زدید با پوشهٔ بازِ VS Code فرق دارد | دستور را در پوشهٔ درست بزنید، یا سرور را با &lrm;`-s user`&lrm; اضافه کنید تا به پوشه وابسته نباشد. |

بستن کامل VS Code در هر سیستم‌عامل:

- **ویندوز:** بستن همهٔ پنجره‌های VS Code (همهٔ پنجره‌ها یک پروسهٔ مشترک دارند).
- **مک:** &lrm;`⌘+Q`&lrm;، نه فقط ضربدر قرمز پنجره.
- **لینوکس:** بستن همهٔ پنجره‌ها؛ اگر لازم بود با &lrm;`pkill -f "code"`&lrm; مطمئن شوید پروسه‌ای باقی نمانده.

## <a id="case-6"></a>مورد ۶: سرورِ &lrm;`.mcp.json`&lrm; می‌گوید «Pending approval»

سرورهایی که در فایل &lrm;`.mcp.json`&lrm; پروژه نوشته شده‌اند با git به همهٔ هم‌تیمی‌ها می‌رسند، پس Claude قبل از اجرایشان از هر کاربر تأیید می‌گیرد. تا تأیید نکنید، به آن سرور وصل نمی‌شود.

#### اگر &lrm;`claude mcp get <name>`&lrm; عبارت «Pending approval» نشان می‌دهد

**آنگاه** یک گفتگوی جدید در همان پوشه باز کنید و وقتی پرسید، سرور را تأیید کنید. فقط اگر فایل را از منبع مورد اعتماد گرفته‌اید.

#### اگر پیشتر اشتباهی «رد» کرده‌اید و دیگر نمی‌پرسد

**آنگاه** انتخاب‌های قبلی را پاک کنید (داخل همان پروژه) و گفتگوی جدید باز کنید:

<div dir="ltr">

```bash
claude mcp reset-project-choices
```

</div>

## <a id="case-7"></a>مورد ۷: Connected است ولی Claude ابزار را نمی‌بیند یا مدام اجازه می‌خواهد

اتصال درست است. مشکل از «استفاده» است، نه «اتصال».

#### اگر Claude می‌گوید این ابزار را ندارد

**آنگاه** ابزارهای MCP در Claude با اسم &lrm;`mcp__<server>__<tool>`&lrm; ظاهر می‌شوند و گاهی Claude باید اول آن‌ها را جستجو کند. مستقیم بخواهید: «از سرور `iran-crypto` استفاده کن و اول ابزارهایش را جستجو کن.» و در &lrm;`/mcp`&lrm; سرور را باز کنید تا لیست ابزارهایش را ببینید.

#### اگر برای هر بار استفاده از ابزار اجازه می‌پرسد

**آنگاه** می‌توانید همهٔ ابزارهای یک سرور را مجاز کنید (فقط برای سرورهایی که به آن‌ها اعتماد دارید). در &lrm;`~/.claude/settings.json`&lrm; (یا &lrm;`.claude/settings.json`&lrm; پروژه):

<div dir="ltr">

```json
{
  "permissions": {
    "allow": ["mcp__iran-crypto"]
  }
}
```

</div>

با &lrm;`/permissions`&lrm; در گفتگو می‌توانید ببینید این تنظیم اعمال شده یا نه.

#### اگر ابزار اجرا می‌شود ولی خطا یا جواب خالی برمی‌گرداند

**آنگاه** مشکل از خودِ سرور یا سرویسِ پشت آن است (کلید، سهمیه، محدودیت منطقه‌ای). برای دیدن جزئیات، Claude را با لاگ اجرا کنید: `claude --debug-file mcp-debug.log` و در فایل نام سرور را جستجو کنید.

## <a id="case-8"></a>مورد ۸: فایل تنظیمات خراب یا JSON نامعتبر است

یک ویرگول یا کوتیشن جا افتاده کافی است تا کل فایل خوانده نشود و سرورها یکی‌یکی دیده نشوند.

#### اگر &lrm;`.mcp.json`&lrm; را دستی ویرایش کرده‌اید

**آنگاه** اول چک کنید JSON درست باشد. ساختار درست:

<div dir="ltr">

```json
{
  "mcpServers": {
    "iran-crypto": {
      "command": "uvx",
      "args": ["iran-crypto-mcp"]
    }
  }
}
```

</div>

**ویندوز:**

<div dir="ltr">

```powershell
python -m json.tool .mcp.json
```

</div>

**مک و لینوکس:**

<div dir="ltr">

```bash
python3 -m json.tool .mcp.json
```

</div>

اگر خطا نداد، JSON درست است و خروجی مرتب چاپ می‌شود. اگر خطا داد، شمارهٔ خطِ مشکل را نشان می‌دهد.

#### اگر می‌خواهید فایل &lrm;`~/.claude.json`&lrm; را دستی ویرایش کنید

**آنگاه** **نکنید.** Claude مدام در این فایل می‌نویسد و ویرایش دستی هم‌زمان ممکن است بازنویسی شود یا فایل را خراب کند. از `claude mcp add/remove` استفاده کنید. اگر ناچارید، همهٔ گفتگوهای Claude را ببندید و قبلش یک نسخهٔ پشتیبان بگیرید.

## <a id="scopes"></a>سرور را کجا اضافه کنیم؟ سه نوع scope

گزینهٔ &lrm;`-s`&lrm; (یا &lrm;`--scope`&lrm;) تعیین می‌کند سرور کجا ذخیره شود و چه کسانی ببینند. پیش‌فرض `local` است.

| scope | چه کسی می‌بیند | کجا ذخیره می‌شود | کی مناسب است |
| --- | --- | --- | --- |
| `local` (پیش‌فرض) | فقط شما، فقط همین پروژه | &lrm;`~/.claude.json`&lrm;، برای مسیر دقیق پوشهٔ پروژه | آزمایش یا کلید شخصی برای یک پروژه. به مسیر پوشه وابسته است. |
| `user` | فقط شما، همهٔ پروژه‌ها | &lrm;`~/.claude.json`&lrm;، در بخش اصلی فایل (نه زیر مسیر یک پروژه) | **ابزارهای شخصیِ همیشگی.** مطمئن‌ترین انتخاب برای رفع مشکل «دیده نمی‌شود». |
| `project` | هرکس که پروژه را از git بگیرد (پس از تأیید) | فایل &lrm;`.mcp.json`&lrm; در پوشهٔ اصلی پروژه | سرورهای مشترک تیم. هرگز کلید داخلش ننویسید. |

موقع `claude mcp remove` اگر &lrm;`-s`&lrm; ندهید، از هر scope که سرور در آن باشد حذف می‌شود.

## <a id="cheatsheet"></a>راهنمای سریع: دستورها و جای فایل‌ها

| دستور | کارش |
| --- | --- |
| &lrm;`claude mcp add <name> -s user -- <command> [args]`&lrm; | اضافه کردن سرور محلی (stdio) برای همهٔ پروژه‌ها |
| &lrm;`claude mcp add --transport http <name> <url>`&lrm; | اضافه کردن سرور از راه دور |
| &lrm;`claude mcp add <name> -e KEY=value -- <command>`&lrm; | اضافه کردن با متغیر محیطی (مثلاً کلید API) |
| `claude mcp list` | لیست سرورها و وضعیتشان (از پوشهٔ پروژه بزنید) |
| &lrm;`claude mcp get <name>`&lrm; | جزئیات یک سرور (ممکن است مقدار کلیدها را هم نشان دهد؛ جایی نفرستید) |
| &lrm;`claude mcp remove <name> [-s scope]`&lrm; | حذف سرور |
| `claude mcp reset-project-choices` | پاک کردن تأیید یا ردِ سرورهای &lrm;`.mcp.json`&lrm; |
| `claude mcp add-from-claude-desktop` | وارد کردن سرورهای Claude Desktop (فقط مک و WSL) |
| `claude --debug-file mcp-debug.log` | اجرا با لاگ کامل (debug) داخل یک فایل |
| &lrm;`/mcp`&lrm; (داخل گفتگو) | وضعیت، لاگین و ابزارهای هر سرور |

### فایل‌ها کجاست؟

| فایل | ویندوز | مک | لینوکس |
| --- | --- | --- | --- |
| تنظیمات و سرورهای شخصی | `C:\Users\<name>\.claude.json` | &lrm;`/Users/<name>/.claude.json`&lrm; | &lrm;`/home/<name>/.claude.json`&lrm; |
| پوشهٔ تنظیمات (settings، حافظه، …) | &lrm;`C:\Users\<name>\.claude\`&lrm; | &lrm;`~/.claude/`&lrm; | &lrm;`~/.claude/`&lrm; |

سرورهای مشترک پروژه در فایل &lrm;`.mcp.json`&lrm; در پوشهٔ اصلی پروژه‌اند (در هر سه سیستم‌عامل یکسان).

## <a id="security"></a>امنیت: قبل از نصب هر سرور MCP

- **سرور MCP یعنی کدی که روی سیستم شما، با دسترسی‌های شما اجرا می‌شود.** دستورهایی مثل &lrm;`uvx <package>`&lrm; یا &lrm;`npx <package>`&lrm; همان لحظه از اینترنت دانلود و اجرا می‌کنند. فقط پکیج‌های مورد اعتماد را نصب کنید؛ اسم پکیج و سازنده‌اش را بررسی کنید.
- **کلید و توکن را در فایلی که به git می‌رود ننویسید.** برای کلیدهای شخصی از &lrm;`-e KEY=value`&lrm; در scope `local` یا `user` استفاده کنید.
- **اسکریپت نصب «curl … | sh» را بدون بررسی اجرا نکنید.** اگر package manager (مثل winget، brew، apt) دارید، همان را ترجیح دهید، یا اسکریپت را اول دانلود و بخوانید.
- **خروجیِ `claude mcp get` و لاگ‌های debug** ممکن است کلید یا آدرس داخلی داشته باشد؛ قبل از فرستادن برای دیگران آن‌ها را پاک کنید.

## اگر هیچ‌کدام جواب نداد

برای اینکه کسی بتواند کمک کند، این‌ها را (بدون کلید و توکن) جمع کنید و بفرستید:

1. سیستم‌عامل و نسخهٔ آن، و اینکه از **ترمینال** یا **افزونهٔ VS Code** استفاده می‌کنید.
2. خروجی `claude --version` و `claude mcp list`.
3. دقیقاً چه دستوری برای اضافه کردن سرور زدید و در کدام پوشه.
4. خروجی اجرای دستیِ سرور ([تست ۳](#test-3) بالا)، با پیام خطای کامل.
5. عکسی از لیست &lrm;`/mcp`&lrm; (وضعیت سرور).
